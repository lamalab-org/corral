# Psychometrics Task Environment

This environment contains synthetic psychometrics tasks. Each dataset is
simulated from a known model, so the ground truth is available for evaluation.
The tasks are designed to require judgement: a simple or fit-only analysis may
give a plausible but misleading conclusion.

## Layout

The importable package is `corral_psychometrics`; the distribution is
`corral-psychometrics`.

```
pyproject.toml                       dependencies and tool configuration
.pre-commit-config.yaml              repository quality checks
build.py                             rebuild and check the whole environment
tests/test_scoring.py                checks every task scores as intended

src/corral_psychometrics/
  paths.py                           where every generated file lives
  env.py                             Corral environment and agent tool policy
  tools.py                           agent-facing workspace and analysis tools
  score.py                           the scorer
  generators/common.py               simulation and fitting shared by all tasks
  generators/level_*/gen_*.py        one module per task: the model its data come from
  generators/level_*/task_*.md       short human-facing task descriptions

artifacts/level_*/task_*/            the files the agent is given
truth/level_*/task_*.json            the answer keys
environments/level_*/tasks_json/     the task definitions
```

Those three trees are generated by `build.py` and committed, so a fresh
checkout can run the tasks without building anything first. Rebuilding uses a
staging directory, validates the new files, and replaces only the selected
tasks. A failed generator leaves the previous task intact. An interruption
during publication leaves a marker that prevents loading until that task is
rebuilt. Do not rebuild data while an evaluation is using it.

Truth files retain their existing date and commit only when their contents,
dataset checksum, seed, and dependency versions are unchanged. Reproducibility
across different numerical-library versions is not guaranteed.

Everything resolves against the checkout by default and needs no
configuration. A different built dataset can be pointed at explicitly, which
also allows two of them in one process:

```python
create_environments(level=1, data_root="/data/psychometrics/v1", work_dir="/runs/exp-42")
```

An install with no checkout to infer the data from -- anything but an editable
install -- passes `data_root` or sets `CORRAL_PSYCHOMETRICS_ROOT` instead.
The wheel contains code; obtain the committed data separately. `build.py` is
a repository development utility, not an installed command.

A workspace is built by copying a task's artifact directory, which holds only
public files; the answer keys live in `truth/`. Each definition lists its
`public_inputs`, and setup fails unless the directory holds exactly those.

Definitions record checksums for every public input. Loading a level hashes
the actual files and checks the definition against its answer key.

A task's level and number are written down once, in its generator's filename;
`paths.task(__file__)` reads them back.

## Setup and building

The project uses `uv` and a local virtual environment. Install the runtime and
development dependencies with:

```bash
uv sync --group dev
uv run pre-commit install
```

The committed data is already built. Regenerate it after changing a generator;
generators run as modules, so any working directory works:

```bash
uv run python build.py --clean   # rebuild selected tasks from scratch
uv run python build.py --check   # build, verify, run naive checks and scoring
uv run python build.py --tasks 3 7
uv run python build.py --data-root /data/psychometrics/v2
```

`--clean` is a compatibility alias for a fresh build; it does not delete
unselected tasks. Tests read the committed data and never regenerate it.

`--check` verifies that the intended answer wins (`--verify`), the obvious
analysis fails (`--naive`), and the scorer gives the intended verdicts.

To run only the scoring integration test:

```bash
uv run python tests/test_scoring.py
```

## Agent environment

Create environments with:

```bash
uv run python -m corral_psychometrics.env --level 1
uv run python -m corral_psychometrics.env --level 2
```

Each task gets an isolated workspace containing only the public files named in
its task definition. The agent receives file tools, `validate_model_syntax`, and
Corral's checkpointed `PythonREPL`, which runs with the workspace as its
working directory. Variables, dataframes and fitted models survive between
calls. NumPy, pandas, SciPy, factor-analyzer and semopy are installed.

The environment does not expose a shell, the generators, the scorer, build
checks, or the `truth/` tree. Preliminary analyses included as task inputs
remain visible. Model syntax uses the lavaan-style notation accepted by semopy; R and
lavaan are not required.

## Scoring

Tasks use either a submitted model or a structured JSON conclusion. When a model
is submitted, the scorer refits it and checks its fit and reported claims. For
classification and decision tasks, it checks the required fields against
results derived from the generated evidence. Every scorer returns a binary
score and a partial diagnostic score.

## Model syntax

Submissions and reference models use lavaan-style syntax such as `=~`, `~~`,
and `~`. The Python implementation fits that syntax with `semopy`; R and the
R `lavaan` package are not required for this repository.

## Quality checks

Run all configured pre-commit checks manually with:

```bash
uv run pre-commit run --all-files
```

## Level 2

Level 2 tasks provide more than a dataset and a direct question. They may include
preliminary analyses, competing interpretations, or multiple files. The agent
must decide what evidence would distinguish the explanations, test the relevant
assumptions, and report a calibrated conclusion.
